  - MEDIUM: Scalar SLM loads for float4 construction — 4 individual reads instead of 1 aligned 128-bit vector load (CUDA uses (float4&) cast).
  - MEDIUM: Missing reqd_sub_group_size(16) on all 4 kernel launch paths.

[2026-02-14] Analyzed kernel getrows (gather rows) SYCL kernels (sk_011). Found 6 optimization opportunities (medium potential).
  - MEDIUM: Missing I32 and BF16 src0 types + non-F32 dst type support — CUDA has two-level type switch covering I32, BF16, F16, F32 src and F32, I32, F16, BF16 dst.
  - MEDIUM: No reqd_sub_group_size(16) on any kernel launch — suboptimal SIMD width on Xe2.
  - MEDIUM: Integer div/mod for batch indexing (i11/i12 = global_id / ne12, % ne12) — expensive; CUDA uses grid-stride loops with grid clamping instead.
  - LOW: No vectorized loads/stores for float gather path.
  - LOW: Unnecessary dpct::has_capability_or_fail(fp16) in get_rows_sycl_float.
  - LOW: k_get_rows_back_float uses nd_range<3> with dim 0 = 1 — could be nd_range<2>.

[2026-02-14] Analyzed kernel dmmv (dequantize matrix-vector multiply) SYCL kernels (sk_010). Found 9 optimization opportunities (high potential).
  - CRITICAL: Work-group sizes only 16-32 threads — CUDA uses 32-256 with dynamic selection. Only 1 hardware thread per XVE, 4-8x throughput loss.
  - HIGH: QK_WARP_SIZE=32 forces SIMD32 on Intel for K-quant kernels — halves occupancy vs native SIMD16.
  - HIGH: Off-by-one boundary bug — K-quant kernels Q2_K/Q3_K/Q4_K/Q6_K use 'row > nrows' instead of 'row >= nrows'.
  - HIGH: No multi-column batching — 1 output column per launch vs CUDA's 8.
  - HIGH: ~620 lines of duplicated K-quant code + 11 identical dispatch functions.
  - MEDIUM: Manual dpct shuffle reduction, no vectorized Y loads, no GLU/bias fusion.
  - LOW: DPCT artifacts, missing BF16, dead GGML_SYCL_F16 code for K-quants.
