## Recent Activity
[2026-03-06] Analyzed vecdotq device functions (sk_008). Found 5 optimization opportunities (medium potential). Key findings: 1361 lines of device helper functions (NOT kernels) called by MMVQ/DMMV. Heavy DPCT artifacts (dp4a, vectorized_binary, byte_level_permute). Inconsistent get_int_from_* helpers (non-aligned 4-byte-load vs aligned single-load). Only 3/20+ formats have reorder (SoA) variants. IQ format loops missing #pragma unroll. DPCT_COMPATIBILITY_TEMP CUDA artifact may incorrectly gate IQ format support.
[2026-03-06] Analyzed kernel quantize_sycl Q8_1 (sk_007). Found 3 optimization opportunities (low potential). Key findings: Already well-implemented with correct sub-group size (16), vectorized vec2 loads/stores, and proper sycl::reduce_over_group reductions. Purely memory-bandwidth bound (0.16 ops/byte). WG size 16 is suboptimal but hardware compensates via concurrent WG scheduling. SoA reorder variant enables cache-friendly layout for downstream matmul. This is a utility kernel with low optimization ROI.
[2026-03-06] Analyzed kernel MUL_MAT_ID (sk_006). Found 5 optimization opportunities (high potential). Key findings: CRITICAL blocking D2H copy of ids tensor creates pipeline stall (30-60% latency). ne12==1 path launches individual MUL_MAT per token-expert pair instead of batched compaction. No GPU-side mm_ids_helper equivalent — host-side sequential expert processing. k_copy_src1_to_contiguous/k_copy_dst_from_contiguous are simple copy kernels but are launched per-expert serially. ~10-20% hardware efficiency.
[2026-03-06] Analyzed kernel outprod (oneMKL GEMM) (sk_005). Found 3 optimization opportunities (low potential). Key findings: This is a oneMKL GEMM wrapper — not a custom kernel, so the GEMM itself is already near-optimal. CRITICAL: missing batch dimension support (ne2>1, ne3>1) forces CPU fallback for batched outprod. Missing GQA broadcasting support. F16 not supported. Hardcoded leading dimensions instead of stride-based. The primary optimization is functional parity with CUDA (batching, F16), not compute performance.
[2026-03-06] Analyzed kernel dequantize_block_sycl (convert) (sk_004). Found 8 optimization opportunities (medium potential). Key findings: inconsistent work-group sizes (16-256) across 22+ kernel variants, pervasive nd_range<3> DPCT artifacts (only 1 of 22 uses nd_range<1>), missing reqd_sub_group_size on 20+ kernels, strided output writes in K-quant formats (stride 32), no vectorized loads except Q4_K, inconsistent #pragma unroll, IQ format lookup tables not cached in SLM. The kernel is purely memory-bandwidth bound (dequantization is trivial compute). Medium potential because the generic path already uses WG=256 and some formats have reorder variants.
[2026-03-06] Analyzed kernel dequantize_mul_mat_vec (DMMV) (sk_003). Found 8 optimization opportunities (high potential). Key findings: CRITICAL K-quant sub-group size mismatch (QK_WARP_SIZE=32 vs Intel native SIMD16 — correctness risk), tiny work-group sizes (16 or 64), no SLM caching, no vectorized loads, strided memory access, extensive DPCT artifacts. Butterfly reduction exceeds sub-group width in K-quant kernels.
[2026-03-06] Analyzed kernel mul_mat_vec_q (MMVQ) (sk_002). Found 7 optimization opportunities (high potential). Key findings: legacy kernels use work-group size of only 16 (should be 256), no SLM caching of shared Y vector, manual shuffle reduction (DPCT artifact), no vectorized loads, reorder support limited to 3/20 formats. This kernel is critical for single-token inference latency.
[2026-03-06] Analyzed kernel mul_mat_q (MMQ) (sk_001). Found 8 optimization opportunities (high potential). Key findings: work-group size 64 (should be 256+), missing reqd_sub_group_size, no XMX/joint_matrix usage, no vectorized loads, CUDA SLM padding patterns.
