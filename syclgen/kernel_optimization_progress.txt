## Recent Activity
[2026-02-14] Analyzed kernel dmmv (dequantize matrix-vector multiply) SYCL kernels (sk_010). Found 9 optimization opportunities (high potential).
  - CRITICAL: Work-group sizes only 16-32 threads — CUDA uses 32-256 with dynamic selection. Only 1 hardware thread per XVE, 4-8x throughput loss.
  - HIGH: QK_WARP_SIZE=32 forces SIMD32 on Intel for K-quant kernels — halves occupancy vs native SIMD16.
  - HIGH: Off-by-one boundary bug — K-quant kernels Q2_K/Q3_K/Q4_K/Q6_K use 'row > nrows' instead of 'row >= nrows'.
  - HIGH: No multi-column batching — 1 output column per launch vs CUDA's 8.
  - HIGH: ~620 lines of duplicated K-quant code + 11 identical dispatch functions.
  - MEDIUM: Manual dpct shuffle reduction, no vectorized Y loads, no GLU/bias fusion.
  - LOW: DPCT artifacts, missing BF16, dead GGML_SYCL_F16 code for K-quants.

[2026-02-14] Analyzed kernel mmvq (quantized matrix-vector multiply) SYCL kernels (sk_009). Found 8 optimization opportunities (high potential).
  - HIGH: One kernel launch per output column — CUDA batches up to 8, causing 4x redundant weight reads
  - HIGH: Non-reorder work-group size only 16 (CUDA uses 128) — minimal memory latency hiding
  - HIGH: 31 duplicated functions (11 kernels + 20 dispatchers) — should be unified template
  - MEDIUM: No GLU/bias fusion — CUDA fuses gate matmul + bias + activation into single kernel
  - MEDIUM: Inconsistent reduction patterns — reorder uses reduce_over_group, non-reorder uses dpct shuffle
  - MEDIUM: GGML_SYCL_MMV_Y=1 vs CUDA rows_per_block=2 — half the row throughput
  - LOW: DPCT artifacts, reorder path assertion crash risk for unusual model dimensions

[2026-02-14] Analyzed kernel mmq (quantized matrix multiply) SYCL kernels (sk_008). Found 9 optimization opportunities (critical potential).
  - CRITICAL: No XMX/tensor core compute path — SYCL_USE_XMX only changes tile sizes, not computation. joint_matrix completely unused. 3-5x potential.
  - HIGH: Tile size mismatch bug — dispatch selects sizes by compute_capability but kernels hardcoded to AMPERE constants
  - HIGH: Tile sizes tuned for NVIDIA Ampere, not Intel Xe2 (different SLM, SIMD width, register file)
  - HIGH: No stream-K partitioning for better EU utilization on small batches (15-40% improvement)
  - MEDIUM: Y data loaded from global memory every K sub-iteration instead of pre-reformatted layout
  - MEDIUM: No reqd_sub_group_size(16), global barriers instead of local barriers
  - MEDIUM: 10 nearly identical dispatch functions should be one template
  - LOW: Missing 8 IQ quant types + MXFP4, pervasive DPCT artifacts

[2026-02-14] Analyzed kernel cpy (copy) SYCL kernels (sk_007). Found 8 optimization opportunities (high potential).

  - HIGH: Scalar copy work-group size is only 32 (SYCL_CPY_BLOCK_SIZE) — should be 256+
  - HIGH: No contiguous fast-path — always performs 12 integer div/mul for 4D index decomposition
  - MEDIUM: No vectorized loads/stores, no #pragma unroll, no reqd_sub_group_size(16)
  - LOW: DPCT artifacts, int32 indices (overflow risk), missing BF16 support
